## 文章作成フロー

```
0. 基本方針の固定（書き始める前に）
   ├─ 誰に向けた文章か（ターゲット読者）
   ├─ 何を伝える文章か（核心メッセージ）
   └─ 読後にどうなってほしいか（ゴール）

1. 企画・構成
   ├─ 目的・ターゲット・ゴールの確認
   ├─ キーワード調査（SEO の場合）
   ├─ 見出し構成（h2/h3/h4）の設計
   └─ 参考記事・情報源の収集（Web 検索）

2. 執筆
   ├─ リード文で興味を引く（結論 or 疑問形 or 共感）
   ├─ 本文は PREP 法 or サンドイッチ法 を基本に
   ├─ 1段落 = 1メッセージ（3〜5行）
   ├─ 箇条書き・太字で読みやすさを確保
   └─ 最後にまとめ + 行動喚起（CTA）

3. 推敲・校正
   ├─ 誤字脱字チェック
   ├─ 一文一意（1文に伝えたいことは1つ）
   ├─ 修飾語は削る（「〜的な」「〜について」等）
   ├─ カタカナ語を減らす / 言い換え
   └─ 音読して違和感がないか確認

4. 納品
   ├─ Markdown 形式で保存（必要に応じて）
   └─ 入稿用にプレーンテキスト or 指定フォーマットで出力
```

## スタイルガイド

### 文体ルール
- **句読点**: 「、」「。」を適切に使う。読点は 1 文に 2〜3 個まで
- **括弧**: カギ括弧「」は強調・会話・引用に。二重カギ括弧『』は使わず、普通のカギ括弧「」を使う
- **数字**: 原則 算用数字（1, 2, 3）。ただし慣用的なものは漢字（一つ, 二つ）
- **日付**: 「2026年7月21日」表記
- **英単語**: 文中の英単語は前後に半角スペース
- **体言止め**: 見出し、短い導入コピー、要点の強調など、意図が明確な場面に限定する
- **語尾調整**: 「です」「ます」「でした」「ます。」ばかり連続しないように調整する
- **断定調**: 根拠が十分にある箇所に限って使う
- **強調**: `<strong>` で囲む
- **感嘆符・疑問符**: 多用しない
- **絵文字**: 使わない

### 禁止表現
- 過度な誇張（「絶対」「必ず」など）— 根拠がない限り使わない
- 二重否定（「ないことはない」→「ある」）
- 同じ接続詞の連続（「また」「そして」の繰り返し）
- 読者を限定しすぎる表現（「あなただけに」など）

### 表記ルール
- `——` は使わない
- `：`（全角コロン）は使わない
- `:`（半角コロン）は使わない
- 文のつなぎや区切りはダッシュではなく、句点 `。` と読点 `、` を使う

### HTML タグ運用
- 補足・注意喚起の囲み: `<blockquote class="article-quote article-quote--info"></blockquote>`
- 引用の囲み: `<blockquote class="article-quote"></blockquote>`
- 表組み: `<table class="article_table">`

### SEO 観点
- タイトルは 30〜40 文字、ディスクリプションは 120 文字以内を目安に
- h1 は 1 ページに 1 つ。h2 → h3 → h4 の階層を守る
- キーワードは自然な文脈で盛り込み、詰め込み禁止
- 内部リンク・外部リンクを適宜配置
- **キーワードリサーチ**: Growth Marketer または OpenSEO MCP から提供されたデータを活用する

### 参照ルール
- 参照を示す場合は、できる限り出典の URL リンクを置く
- URL を記載する場合は、本文や指示書に入れる前に `curl` で実在する URL か確認する

### 検収ルール
- Web 記事の更新作業では、`skills/web-article-update` を前提に、更新前後の DB 確認と `curl` 確認まで含めて検収する
- 検収結果は、対象記事 ID、slug、更新フィールド、置換件数または更新文字数、スナップショット有無、DB 確認結果、`curl` 確認結果を押さえる

### 商品説明文のコツ
- スペック（機能）→ ベネフィット（顧客メリット）の順で
- 「〜できます」ではなく「〜が実現します」
- 五感に訴える表現を取り入れる
- 比較対象を示すと伝わりやすい

## 注意事項

- **事実確認を徹底する** — 不確かな情報は Web 調査で裏付けを取る
- **著作権を尊重する** — 他サイトの文章の丸写しは禁止。参考にした情報は出典を明記
- **コードは書かない** — マークアップが必要な場合は Markup Engineer に引き継ぐ
- **ターゲット読者を意識する** — 専門用語を使うときは必ず説明を添える
- **修正依頼は歓迎する** — ニュアンスの違いは積極的に調整する
