# ホストの真の 80秒放置（ses_f97f152a）

## 優先度
🟢 低

## 対象
- 計画書: `documents/plans/dev/issues/20260904_host-80s-idle.md`
- 関連ファイル: `artifacts/daily/20260904_logbook.md`, `~/.local/share/opencode/opencode.db`, `~/.config/opencode/opencode.json` (host)

## 指摘事項
`20260904_logbook.md` を `rm` して `DAILY_LIMIT` 回避し `host-v1-80s-1534` (15:34) を `launchd` でスケジュールしたが、Docker 優先のため未実行。`ses_f97f152a` は `opencode` v1 (1.18.27) で `plugin: ["opencode-autopilot-logbook"]` の `DailyLogbookPlugin` が `default` の `object` 化でロード失敗しているため先に `hybrid.ts` の `typeof` 衝突（残件1）を解消してから再スケジュールが必要。

## 改善案
- `hybrid.ts` の `default` を `opencode` v1 用の `function` と `opencode2` 用の `object` の両立（残件1）を解消してから `20260904_logbook.md` を `rm` し `DAILY_LIMIT` 回避して `ses_f97f152a` (Orca の `opencode -s` TUI) で 80秒間無操作放置。`host-v1-80s-1534` (15:34) の `launchd` で `ls` / `wc -l` / `tail` / `sqlite` で検証
- `OPENCODE_API_KEY` (sk-V2g3...) は `symphony_workspaces/.env` の `OPENCODE_GO_API_KEY` で `opencode` v1 の `OPENCODE_GO` (Omen Alpha) としては認識されるが `opencode` v1 の `session.idle` は `Bun.write` の file-direct にフォールバックするため APIキーなしでも `artifacts/daily` への書き込みは可能（`e2e --direct` と同一パス）

## 振る舞い（BDD）
- **正常系:** `ses_f97f152a` (Orca の `opencode -s` TUI) で 80秒間無操作放置で `artifacts/daily/20260904_logbook.md` が `Bun.write` で新規作成（`DAILY_LIMIT` 回避のため `rm` 後の `0` から）。`sqlite` で `SELECT title FROM session WHERE title LIKE '[daily-logbook:auto]%'` に `20260904` が追加されること
- **異常系:** `ses_f97f152a` が `loop` のみで `daily-logbook plugin loaded` が出ない場合は `hybrid.ts` の `default` の `typeof` 衝突でロード失敗。`artifacts/daily` が `No such file` のままの場合は `hello` 未到達で `session` 未生成
- **データ例:** `ses_f97f152a` at `opencode --session ses_f97f152a1ffeqnGaDi3H6EOu8W` (1:09, `U+`), `artifacts/daily/20260904_logbook.md` 29行 → `rm` 後 `0` → 80秒放置で 40+行
