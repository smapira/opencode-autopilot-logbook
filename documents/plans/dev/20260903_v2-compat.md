# Plan: opencode v2 互換検証と移行 — daily-logbook plugin (Issue 20260903)

## 背景
- 現行 `opencode-autopilot-logbook` v1.2.0 は V1 Plugin API (`import type { Plugin, PluginInput } from "@opencode-ai/plugin"` / `export const DailyLogbookPlugin: Plugin = async ({ client, directory }) => ({ event })`) に完全依存
- V2では Plugin APIが intentional breaking change。公式 [Migrate from V1](https://opencode.ai/v2/docs/migrate-v1) に `V1 plugins will not work in V2.` と明記。詳細な移行ガイドはbeta期間中で未確定
- 現行 `package.json` は `@opencode-ai/plugin ^1.0.0` / `.opencode/package.json 1.18.15`。V2は `@opencode-ai/plugin@beta` (現 `0.0.0-beta.18999`) と `opencode@beta` が必須。V1の `opencode` バイナリは `1.18.27` (anomalyco tap) のみで `opencode2` という別バイナリ名は存在しない（docs上の `opencode2` 表記はbeta channelのエイリアス）
- ユーザリクエスト: 「このプラグインがv2で動作するか検証」→ 検証結果は **NG（非互換）**。本計画は検証根拠と移行のためのBDDタスク分解を定義する

## 目標
- V2で `session.idle` → 日報生成が同一振る舞いで完遂することを検証可能にする
- V2の `Plugin.define({ id, setup(ctx) })` + `ctx.event.subscribe` + `ctx.session.*` への移行を、BDDでタスク分割して実装可能にする
- 既存の純粋ロジック（throttle/daily-limit/secret masking/usage集計/template置換）は回帰なく温存
- デフォルト設定で既存V1利用者の挙動を壊さない（coexist or major bumpの判断材料を提供）

## 検証結果サマリ

### 結論: 現行コードはV2で動作しない
1. **型・形状**: V1 `PluginInput { client, directory, project, worktree }` → V2 `PluginContext { location, options, agent, catalog, command, integration, plugin, reference, skill, event, session, storage, ... }` へ全面変更。`client.app.log` / `client.session.*` / `return { event }` はV2に存在しない。V2 betaの `Context` は `app: { name, version, channel }` のみで `log` メソッドを持たない。`Logger` は再設計が必要（`type Logger = PluginInput["client"]` は消滅）
2. **依存**: `1.18.x` の `dist/v2/promise/context.d.ts` は8ドメインのみ（agent/aisdk/catalog/command/integration/plugin/reference/skill ※aisdk含む）。V2 docsが示す `ctx.session/prompt/generate/storage/event` は `beta` でのみ提供
3. **Config**: `opencode.json` の `plugin: [...]` → V2 `plugins: [...]`（object形式 `{package, options}`）への移行がMigrateガイドで示唆されるが、betaでは未ドキュメントで共存可否はE2Eで確定が必要。ファイル配置も `.opencode/plugin/` と `.opencode/plugins/` をV2は両方読むが新規は `plugins/` 推奨。現行 `.opencode/opencode.json` は `permissions/mcp/skills` のみで `plugin` キー自体なし

### 参考: V2 Plugin 最小形 (https://opencode.ai/v2/docs/build/plugins) ※promise版は `subscribe({signal}) => AsyncIterable<V2Event>` / effect版は `subscribe(type): Stream` で形状が異なる
```ts
import { Plugin } from "@opencode-ai/plugin"
export default Plugin.define({
  id: "smapira.daily-logbook",
  async setup(ctx) {
    const controller = new AbortController()
    void (async () => {
      // promise: type引数なし、ループ内でフィルタ。 effect: ctx.event.subscribe("session.idle")
      for await (const event of ctx.event.subscribe({ signal: controller.signal })) {
        if (event.type === "session.idle") {
          const sessionID = (event as { data: { sessionID: string } }).data.sessionID // V2は data, V1は properties
        }
      }
    })()
    return () => controller.abort() // setupは Promise<Cleanup|void>, Cleanup = () => Promise<void>|void
  }
})
```
**V1→V2 API対照（要型確認）**:
| V1 | V2 beta (promise) |
|---|---|
| `client.session.get({ path:{id} })` | `ctx.session.get({ sessionID })` |
| `client.session.messages({ path:{id} })` | `ctx.session.context({ sessionID })` |
| `client.session.create({ body:{title} })` | `ctx.session.create({ title })` |
| `client.session.promptAsync({ path:{id}, body:{parts:[{type,text}]} })` | `ctx.session.prompt({ sessionID, text })` / `ctx.session.generate` |
| `event.properties.sessionID` | `event.data.sessionID` |
| `client.app.log` | なし（`ctx.app`は `{name,version,channel}` のみ。要代替: console / host log調査） |
| `directory` | `ctx.location.directory` |

## BDD タスク分解

### TASK-1: Plugin定義のV2移行
- **振る舞い**: `Plugin.define({ id, setup })` で定義したとき `opencode service status` (beta channel) / `ctx.plugin.list()` でactiveとして列挙される
- **正常系**:
  - `export default Plugin.define({ id: "smapira.daily-logbook", setup })` が `.opencode/plugins/daily-logbook/index.ts` からロードされる
  - `setup` が `() => controller.abort()` のcleanup（`Cleanup = () => Promise<void>|void`）を返し、unload時に購読が停止する（`setup` 自体は `Promise<Cleanup|void>`）
- **異常系**: V1形式 `export const DailyLogbookPlugin` を残すとV2で無視（warningのみ）
- **エッジ**: `id` 重複時に後勝ちで上書きされることを確認
- **データ例**: `id="smapira.daily-logbook"`, `setup(ctx) { console.log(ctx.app.version, ctx.location.directory) }` // ctx.appは {name,version,channel} のみ
- **実装**: `daily-logbook.ts` をV2 entryに分割 or 互換分岐。`package.json: dependencies."@opencode-ai/plugin":"beta"` へ更新。`type:"module"` 維持。`daily-logbook.ts:77 type Logger = PluginInput["client"]` はV2で消滅するためLogger抽象をTASK-4へ移設

### TASK-2: イベント購読 `session.idle` のV2化
- **振る舞い**: `session.idle` のみに反応し日報生成を1回トリガー
- **正常系**:
  - `event.type==="session.idle"` のとき `event.data.sessionID` を取得し生成フローへ（V2 beta: `V2Event { type:"session.idle", data:{ sessionID } }`。V1の `properties` ではない）
  - `session.created / server.connected / installation.updated` では何もしない（promise版は `subscribe({signal}) => AsyncIterable<V2Event>` で全イベントが流れ、ループ内で `if(type==="session.idle")` フィルタ）
- **異常系**: `event.data.sessionID` 不在時は代替ログでskip（V2の `ctx.app.log` は存在しないため `console.warn` 等への置換はTASK-4で確定）
- **エッジ**:
  - `AbortSignal` での購読解除がplugin unload時に確実に呼ばれる（`return () => controller.abort()`）
  - 連続idleはTASK-6のthrottleで抑止
- **データ例**: `event={type:"session.idle", data:{sessionID:"ses_abc123"}}` // V1では properties

### TASK-3: セッション操作のV2移行 (`client.session.*` → `ctx.session.*`)
- **振る舞い**: 対象セッションの取得・新規作成・プロンプト送信がV2 clientと同じI/Oで完遂
- **正常系** (beta promiseのフラット形状):
  - `ctx.session.get({ sessionID })` → `title` 取得（V1: `client.session.get({ path:{id} })` → `.data.title`）
  - `ctx.session.create({ title: "[daily-logbook:auto] 20260903" })` → `sessionID` 取得（V1: `{ body:{title} }`）
  - `ctx.session.prompt({ sessionID, text: prompt })` または `ctx.session.generate` で日報指示を送信（V1: `promptAsync({ path:{id}, body:{parts:[{type,text}]} })`）
  - 旧 `client.session.messages({ path:{id} })` → V2 `ctx.session.context({ sessionID })` へ読替（transcript取得）
- **異常系**:
  - `get` がerror → 代替ログで中断（既存 `logError` 相当だが `client.app.log` 非存在のため要再設計）
  - `create` / `prompt` がerror → 同様に中断、inFlightは必ず解除
- **エッジ**: タイトルが `GENERATED_TITLE_PREFIX="[daily-logbook:auto]"` 始まりならskip（自己生成無限ループ防止）
- **データ例**: `sessionID="ses_src_001"` → 生成 `ses_gen_002` → `prompt: "Create daily logbook..."`（V2は `text` フラット、V1は `parts`）

### TASK-4: ログ・ロケーション解決のV2化
- **振る舞い**: 構造化ログと出力先パス解決がV2コンテキストで維持
- **正常系**:
  - `ctx.location.directory` （`Location.Info`）が旧 `directory` と同値で `resolve(directory, outputDir, "${date}_logbook.md")` が正しく解決
  - ログはV2で `ctx.app.log` が存在しない（`ctx.app` は `{name,version,channel}` のみ）。代替として `console.warn/error` または hostが提供するロガー（要beta E2Eで確定）を `service:"daily-logbook-plugin"` 付きで出力。TASK-1で消滅した `type Logger = PluginInput["client"]` の置換先をここで確定
- **異常系**: ログ失敗は本流を壊さない（try/catch no-op、既存 `logWarn/logError` のtry/catch構造は維持しつつ中身を上記代替に差替）
- **エッジ**: `OPENCODE_DAILY_LOGBOOK_OUTPUT_DIR` 相対 vs `resolve` 絶対の使い分け（dailyLimit時の絶対パス化）を維持
- **データ例**: `directory="/proj" + outputDir="artifacts/daily" => "/proj/artifacts/daily/20260903_logbook.md"`

### TASK-5: 純粋ロジックの温存（回帰対象）
- **振る舞い**: 既存の純粋関数はimportパス変更のみでV2でもテストがグリーン
- **正常系**:
  - `maskSecrets("sk-abcdef12345 Bearer xxx") => "*** ***"`
  - `buildTranscript(messages.slice(-80))` → 12,000文字 truncate、内 `maskSecrets` 先行
  - `formatUsageTable(stats, date)` → markdown table
  - `replaceTemplateVariables(template, sessionId, now, outputDir, usageTable)` → `{{ usage }}`/`{{ usageTable }}` 等を関数置換で安全に展開
- **異常系**: `isWithinWindow(undefined, now, 90000) => false`
- **エッジ**:
  - `OPENCODE_DAILY_LOGBOOK_THROTTLE_MS="invalid"` → デフォルト `90000` にフォールバック
  - `isDailyLogbookExists(directory, outputDir, date)` はV2でも `existsSync` ベースで再起動跨ぎの重複防止
  - `$` 含む `usageTable` の置換が `String.replace(fn)` で壊れない
- **データ例**: `SECRET_PATTERNS` 9種（private-key, `sk-`, `Bearer`, `AKIA`, `ghp_`, `github_pat_`, `xoxb-`, `eyJ...`, `password:=`）

### TASK-6: 重複抑止・DailyLimitのV2対応
- **振る舞い**: 同一セッション連打と同日多重起動をV2非同期subscribeでも抑止
- **正常系**:
  - `inFlightSessionIds.has(id)` または `isWithinWindow(last, now, window)` ならskip
  - `dailyLimitInFlightByDate.has(date)` なら `warn` でskip
  - `isDailyLogbookExists` がtrueなら `warn` でskip
- **異常系**: `OPENCODE_DAILY_LOGBOOK_DAILY_LIMIT=true` かつ `OPENCODE_DAILY_LOGBOOK_TEMPLATE` 設定時は警告しdaily-limit checkをskip（ファイル名不明のため）
- **エッジ**: 2セッション同時idleでも日付キーで1回のみ生成。`finally` で `inFlightSessionIds.delete` / `dailyLimitInFlightByDate.delete` を必ず実行
- **データ例**: `date="20260903"`, `DUPLICATE_WINDOW_MS=90_000`, `recentlyTriggeredAtBySessionId: Map<sessionID, timestamp>`

### TASK-7: Config/配置/公開のV2適合
- **振る舞い**: V2形式でもプラグインが自動ロードされ `opencode` (beta channel) が起動
- **正常系**:
  - `opencode.json` の `plugin: ["opencode-autopilot-logbook"]` → `plugins: ["opencode-autopilot-logbook", {package:"./plugins/local", options:{...}}]` に変換してもV1/V2共存で警告なし（※betaでは未ドキュメントのためE2Eで確定・要公式追従）
  - `.opencode/plugins/` 配置がV2推奨（V2は `plugin/` と `plugins/` 両方を読むが新規は `plugins/`）
- **異常系**: 旧 `plugin` フィールドのみのままV2ではプラグイン未ロード
- **エッジ**: 現行 `package.json` は `main: dist/index.js` のみで `exports: {".":"./src/index.ts","./rpc":...}` は未存在。V2でrpc exportが必要になった場合の `exports` 追加可否を検証、`type:"module"` 維持
- **データ例**: 移行前 `{plugin:["opencode-example-plugin", ["./plugin/local.ts",{enabled:true}]]}` → 移行後 `{plugins:["opencode-example-plugin", {package:"./plugin/local.ts", options:{enabled:true}}]}`

### TASK-8: ビルド・依存・型のV2適合
- **振る舞い**: `bun build` と `tsgo --noEmit` がV2型でパス
- **正常系**:

- **データ例**: `bun run build && bun test` がCIでグリーン

### TASK-9: v2実環境E2E検証
- **振る舞い**: 実際に `opencode` (beta channel) 上で `session.idle` → `artifacts/daily/YYYYMMDD_logbook.md` が生成
- **正常系**:
  - `opencode --standalone` (beta) 起動 → 手動idle発火 → 生成ファイルがappend/updateで作成、重複なし
  - `OPENCODE_DAILY_LOGBOOK_DAILY_LIMIT=true` で2回目idleはskip
  - `OPENCODE_DAILY_LOGBOOK_INCLUDE_TRANSCRIPT=false` でtranscriptなしのpromptが送信

- **データ例**: `artifacts/daily/20260903_logbook.md` に `Cost (本日/セッション) | $2.31 / $0.21` 付きで生成

## 非機能要件
- `opencode.db` は15GB超でも `project_id` + `date(datetime(time_created/1000,'unixepoch','localtime'))` の絞り込みで数百行なら <50ms。現行の `date(datetime(...))` を維持（将来遅延が顕在化したら `time_created >= ? AND < ?` へ切替）
- read-only open: `new Database(path, { readonly: true })` + `try/finally close`。WALでもSELECT可
- 全クエリは `?` バインド、文字列補間禁止
- `~` 展開は `homedir()+join()`、`directory` 正規化は `resolve()` で末尾 `/` 除去
- 依存追加なし: `bun:sqlite` はランタイム供給
